⚡ Split-Planner Benchmark

When a structure fractures, the runtime runs a split planner — a topology-diff that decides which existing Rapier bodies to reuse (keep their handle + colliders, the cheapest edit) versus which fragments need a new body. The old planner padded this to a dense O(max(M,N)³) Hungarian, so a single cascade into a few hundred fragments could stall a frame for tens-to-hundreds of milliseconds. The shipping planner solves it per connected component with an argmax fast path — provably the same optimal assignment, in near-linear time. This page measures the pure planner (no physics, no WASM) so you can watch the difference live.

Planner cost vs. fragment count (log–log)

Lower is better. The amber line (old dense Hungarian) rockets past the 60 fps frame budget; the green line (connected components) stays flat and keeps going far past where the old planner is even feasible.
